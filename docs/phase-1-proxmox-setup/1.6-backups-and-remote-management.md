# 1.6 — Backups and Remote Management

## Objective
The objective of this step was to make sure the Proxmox environment could be managed reliably after the initial setup and to review the backup and recovery features that would be used as the homelab expanded.

Because the Proxmox host would be running multiple virtual machines, I wanted to understand how snapshots and backups could be used before making major configuration changes.

I also wanted to make sure that I could manage the Proxmox server remotely instead of needing to physically connect a monitor and keyboard every time I wanted to work on the homelab.

## Configuration
Remote administration was configured using two methods.

### Local Network Access

While connected to my home network, the Proxmox web interface could be accessed using the host's local IPv4 address.

This allowed me to administer the server from my main PC without directly using the physical Proxmox system.

### Tailscale Remote Access

Tailscale was configured to provide remote access to the Proxmox host from other devices.

The Proxmox server was added to my Tailscale network, which provided it with a separate Tailscale IP address.

Using this address allowed me to reach the Proxmox web interface from another device, such as my MacBook, while connected through Tailscale.

### Backup Storage

The secondary 2 TB HDD was configured to support Proxmox backup files.

The storage content configuration included support for:

- VZDump backup files
- ISO images
- Container templates

This provides a dedicated location that can be used for VM backups as the environment expands.

## Steps Performed
1. Confirmed that the Proxmox web interface could be reached from another computer on the local network.
2. Installed and configured Tailscale for the Proxmox host.
3. Added the Proxmox server to the Tailscale network.
4. Confirmed that a Tailscale IP address was assigned to the host.
5. Installed or connected the Tailscale application on another device.
6. Used the Proxmox host's Tailscale IP address to open the Proxmox web interface remotely.
7. Confirmed that the normal Proxmox login page was accessible through Tailscale.
8. Reviewed the snapshot functionality available for virtual machines in Proxmox.
9. Reviewed the Proxmox backup options and VZDump backup capability.
10. Verified that the secondary HDD was configured to support VZDump backup files.

## Verification
Remote management was verified using both local and Tailscale-based access.

I confirmed that:

- The Proxmox web interface could be reached using the host's local IPv4 address.
- The server could be managed without directly using the physical computer.
- The Proxmox host appeared as a device within Tailscale.
- The host received a Tailscale IP address.
- I could use my MacBook to access the Proxmox login page using the Tailscale IP.
- The same Proxmox management interface was available through both local and remote access methods.
- The secondary HDD was configured to support Proxmox backup files.
- Snapshot and backup functionality was available for future virtual machines.

This confirmed that the Proxmox environment could be administered remotely and that storage had been prepared for future backup operations.

## Issues Encountered
There were no major issues while configuring Tailscale once the Proxmox network and repository configuration were working correctly.

Earlier in the setup process, I experienced an issue where the Proxmox web interface was temporarily unavailable after the physical host was restarted. After restarting the system and confirming that the network connection was functioning correctly, access was restored.

This reinforced the importance of verifying that the physical host, network connection, and Proxmox services are running before assuming that a remote access service is causing the problem.

## What I Learned
This step helped me better understand how servers can be managed remotely and how virtualization platforms provide tools for protecting virtual machines.

Some of the main things I learned included:

- How a Proxmox server can operate without needing a monitor or keyboard for normal administration.
- How the Proxmox web interface allows a system administrator to manage the host remotely.
- How local network access differs from remote access through Tailscale.
- How Tailscale can create a secure connection between devices and provide an additional IP address for remote management.
- How I can access my homelab from another device while away from the physical Proxmox system.
- Why maintaining a stable Ethernet connection on the Proxmox host is important for reliable remote access.
- How Proxmox provides snapshot functionality for virtual machines.
- How VM backups can be stored separately from the primary virtual machine storage.
- Why snapshots and backups serve different purposes when protecting virtual machines.
- Why having recovery options available before making major changes is important when managing servers.

Overall, this step made the homelab much more practical because I no longer needed to physically interact with the Proxmox host every time I wanted to manage the environment.

It also introduced me to backup and recovery concepts that will become more important as I add additional virtual machines and services.
