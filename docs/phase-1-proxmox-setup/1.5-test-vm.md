# 1.5 - Test VM

## Objective
The objective of this step was to learn how to allocate the Proxmox host's resources to create and run a virtual machine successfully.

The first virtual machine I wanted to deploy was a Windows Server system. This VM would eventually become the administrative foundation for the next phase of the homelab, where I plan to work with services such as Active Directory and other business-focused technologies.

For this phase, the goal was only to confirm that Windows Server could be created, installed, and run successfully inside Proxmox. Additional Windows Server configuration would be saved for Phase 2.

This step also gave me hands-on experience with assigning virtual CPU, memory, storage, installation media, and virtual hardware to a VM.

## Configuration
The first virtual machine created in Proxmox was a Windows Server VM that would later be used as the main administrative server for the homelab.

The VM was configured with the following settings:

- **VM Name:** DC01
- **VM ID:** 100
- **Operating System:** Windows Server 2025 Evaluation
- **Firmware:** UEFI
- **Virtual Disk Size:** 64 GB
- **Disk Type:** SCSI
- **Primary VM Storage:** local-lvm
- **TPM Storage:** local-lvm
- **QEMU Guest Agent:** Enabled
- **Windows Server ISO:** Attached as installation media
- **VirtIO Driver ISO:** Attached to provide Windows with the required virtual hardware drivers

The VM was configured to use VirtIO-based virtual hardware so that Windows Server could properly interact with the storage and other virtualized devices provided by Proxmox.

During installation, the VirtIO driver ISO was used to load the Red Hat VirtIO SCSI storage driver so that the Windows Server installer could detect the 64 GB virtual disk.

CPU and memory resources were also allocated to the VM based on the available resources of the Proxmox host, while keeping enough capacity available for future virtual machines.

## Steps Performed
1. Created a new virtual machine in the Proxmox web interface.
2. Assigned the VM the name `DC01` and VM ID `100`.
3. Selected the Windows Server 2025 Evaluation ISO as the installation media.
4. Configured the VM to use UEFI firmware.
5. Created a 64 GB virtual disk using the SCSI interface.
6. Stored the VM disk and TPM-related storage on `local-lvm`.
7. Enabled the QEMU Guest Agent option for the VM.
8. Attached the VirtIO driver ISO in addition to the Windows Server installation ISO.
9. Started the virtual machine and booted into the Windows Server installer.
10. During Windows Setup, the virtual disk was not immediately available, so I used the **Load Driver** option.
11. Browsed to the VirtIO driver ISO and loaded the appropriate Red Hat VirtIO SCSI driver.
12. After the driver loaded, the 64 GB virtual disk became available in the Windows Server installer.
13. Selected the virtual disk and completed the Windows Server installation.
14. Booted into the Windows Server desktop for the first time.
15. Installed the 64-bit VirtIO/QEMU Guest Agent inside Windows Server.
16. Restarted the virtual machine to make sure the guest system loaded normally after installation.

## Verification
The VM deployment was considered successful after confirming that:

- The Windows Server VM could start successfully from Proxmox.
- The Windows Server installation completed without failing.
- The 64 GB virtual disk was correctly detected after loading the VirtIO SCSI driver.
- Windows Server successfully booted to the desktop.
- The VirtIO/QEMU Guest Agent installation completed.
- The VM restarted successfully and continued to boot normally.
- The VM appeared as an operational guest system in the Proxmox web interface.

At this point, the VM was ready for future Windows Server configuration in Phase 2.

## Issues Encountered
The main issue during VM deployment was that the Windows Server installer could not initially detect the virtual hard disk.

Because the VM used a VirtIO SCSI disk, Windows Server did not have the required storage driver available by default.

To resolve the issue:

1. I selected **Load Driver** during Windows Setup.
2. I browsed to the attached VirtIO driver ISO.
3. I located and loaded the appropriate Red Hat VirtIO SCSI driver.
4. After the driver was loaded, the 64 GB virtual disk appeared and could be selected for installation.

There was also some confusion during the installation process about which VirtIO driver directory to use, but after selecting the correct storage driver, the installation continued normally.

This was the first time I had to manually provide a virtualization driver during an operating system installation.

## What I Learned
Creating the first virtual machine helped me better understand how Proxmox divides the physical host's resources among virtual systems.

Some of the main things I learned included:

- How to create and configure a virtual machine in Proxmox.
- How physical CPU, memory, and storage resources are allocated to virtual machines.
- How ISO images are mounted as virtual installation media.
- The purpose of virtual disks and how Proxmox presents them to the guest operating system.
- Why VirtIO drivers are used with Windows virtual machines in Proxmox.
- How to manually load a storage driver when Windows cannot detect a virtual disk.
- The difference between the physical Proxmox host and the guest operating systems running on top of it.
- How a Windows Server VM can serve as the foundation for future services such as Active Directory.
- How the QEMU Guest Agent helps improve communication between Proxmox and the guest operating system.
- How to install an operating system inside a VM and verify that it can successfully reboot and operate independently.

Overall, this was an important step because it was the first time I created a complete virtual machine from the ground up on my own dedicated hypervisor.
