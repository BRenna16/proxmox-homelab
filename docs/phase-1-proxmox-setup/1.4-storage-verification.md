# 1.4 — Storage Verification

## Objective

The objective of this step was to verify that the Proxmox host's storage was configured correctly before deploying virtual machines.

Because the system uses both a 500 GB SSD and a 2 TB HDD, I wanted to make sure each drive had a clear purpose and that Proxmox could properly use both of them.

The SSD was intended for the Proxmox installation and faster virtual machine storage, while the larger HDD was intended for supporting files such as ISO images, backups, and container templates.

## Configuration

The Proxmox host uses two physical storage drives:

### 500 GB Western Digital SSD

The SSD is used as the primary Proxmox storage device.

It contains:

- The Proxmox VE installation
- `local` directory storage
- `local-lvm` LVM-thin storage
- Primary storage for virtual machine disks

Using the SSD for the hypervisor and VM disks provides better performance for the virtual machines running on the host.

### 2 TB Seagate HDD

The secondary 2 TB HDD was configured as additional directory storage.

It was prepared and added to Proxmox so it could be used for:

- ISO images
- VZDump backup files
- Container templates
- Other larger supporting files used by the homelab

Examples of files stored on this drive include installation media such as the Windows Server ISO and VirtIO driver ISO.

## Steps Performed

1. Opened the Proxmox storage and disk configuration from the web interface.
2. Verified that the 500 GB SSD was being used for the Proxmox installation and existing local storage.
3. Identified the secondary 2 TB Seagate HDD.
4. Wiped the secondary drive so it could be configured for Proxmox.
5. Formatted the drive with an appropriate filesystem.
6. Added the HDD to Proxmox as directory-based storage.
7. Configured the storage content types to allow the HDD to store:
   - ISO images
   - VZDump backup files
   - Container templates
8. Verified that both physical drives appeared correctly in the Proxmox interface.
9. Checked the health status of the drives before continuing with the lab.
10. Confirmed that the secondary storage could be selected when uploading ISO images and other files.

## Verification

The storage configuration was verified through the Proxmox web interface.

I confirmed that:

- Both physical drives were recognized by Proxmox.
- The 500 GB SSD was available for Proxmox and virtual machine storage.
- The 2 TB HDD was successfully added as additional directory storage.
- The correct content types were enabled on the secondary HDD.
- ISO images could be stored on the secondary drive.
- Both drives reported a healthy status during verification.

After the storage configuration was completed, the system was ready to store virtual machine disks, installation media, and backup files.

## Issues Encountered

There were no major hardware issues with either storage drive.

The main configuration requirement was making sure the secondary HDD was properly wiped, formatted, and added to Proxmox with the correct content types.

The default storage configuration did not automatically provide the exact layout I wanted for the homelab, so I had to review the storage settings and configure the second drive for ISO images, backups, and templates.

After making those changes, the drive was available for use as intended.

## What I Learned

This step helped me better understand how Proxmox separates physical storage from the different types of data stored within the virtualization environment.

Some of the main things I learned included:

- How Proxmox detects and manages multiple physical storage drives.
- The difference between directory storage and LVM-thin storage.
- Why SSD storage is useful for virtual machine disks where performance is more important.
- How a larger HDD can be used for ISO images, backups, and other files that do not require the same level of performance.
- How to wipe and prepare an additional drive for use in Proxmox.
- How Proxmox content types determine what kinds of files can be stored in a storage location.
- Why planning storage roles before creating virtual machines helps keep the environment more organized.

Overall, this step gave me a better understanding of how storage can be organized in a virtualization environment and how different drives can be assigned different responsibilities based on capacity and performance.
