# 1.1 - Proxmox Installation

## Objective
The objective of this project was to gain hands-on experience with virtualization and system administration outside of my normal course material. I wanted to build a dedicated environment where I could learn through practical experience and become more familiar with the types of technologies and responsibilities involved in a system administrator role.

Installing Proxmox VE provided the foundation for this homelab and gave me a platform where I could practice creating and managing virtual machines while eventually working with technologies I had little or no previous hands-on experience with, including Active Directory, Windows Server, Microsoft Azure, and Proxmox itself.

My overall goal is to develop a stronger understanding of virtualization and how multiple systems and services can work together within a simulated business IT environment.

## Hardware Used
The Proxmox host was installed on an older desktop PC that I repurposed specifically for the homelab.

- CPU: Intel Core i7-8700K
- Memory: 16 GB DDR4 RAM 3000 MHz
- Primary Storage: 500 GB Western Digital SSD
- Secondary Storage: 2 TB Seagate HDD
- Purpose: Dedicated Proxmox homelab host

I chose to dedicate this system entirely to the homelab so it could run multiple virtual machines without competing with normal desktop workloads.

## Configuration
Proxmox VE was installed on the 500 GB Western Digital SSD so the hypervisor and primary virtual machine storage could use the faster drive.

The 2 TB Seagate HDD was configured as additional storage for larger files and resources that did not need to remain on the SSD.

### Storage Configuration

- **500 GB Western Digital SSD**
  - Proxmox VE installation
  - `local` directory storage
  - `local-lvm` LVM-thin storage
  - Primary storage location for virtual machine disks

- **2 TB Seagate HDD**
  - Wiped and formatted as `ext4`
  - Added to Proxmox as directory storage named `hdd-storage`
  - Configured to store:
    - ISO images
    - VZDump backup files
    - Container templates

This setup allows virtual machines to take advantage of the faster SSD while using the larger HDD for installation media, backups, and other supporting files.

### Network Configuration

The Proxmox host was configured to use a wired Ethernet connection rather than Wi-Fi. Keeping the system connected through Ethernet provided a more stable and reliable connection for managing the server and accessing virtual machines.

During the initial setup, the IPv4 network settings were configured manually. This included setting the management IP address and the correct default gateway/router information for the local network.

The Proxmox hostname was configured as:

`pve`

The host was kept connected through Ethernet to avoid connectivity issues and to ensure consistent access to the Proxmox web management interface.

### Administrator Configuration

During installation, the Proxmox administrator credentials and contact email were configured.

For security reasons, the actual password and email address are not included in this repository.

### BIOS and Boot Configuration

Before installing Proxmox VE, I reviewed the system BIOS settings to make sure the hardware was properly configured for virtualization.

The following changes and checks were made:

- Verified that CPU virtualization features were enabled.
- Disabled XMP to prioritize system stability for the homelab.
- Configured the system boot settings so the Proxmox installation media could be used during setup.
- After installation, verified that the system booted directly into Proxmox automatically.

These settings helped ensure that the system was ready to run virtual machines reliably and that the Proxmox host would start normally after a reboot.

## Steps Performed

1. Downloaded the Proxmox VE ISO file onto another computer.
2. Used a 64 GB USB flash drive as the installation media.
3. Used Rufus to properly write the Proxmox ISO to the USB drive and make it bootable.
4. Inserted the USB drive into the dedicated homelab PC.
5. Entered the system BIOS and verified the required virtualization and boot settings.
6. Booted the system from the Proxmox installation USB.
7. Started the Proxmox VE installation process.
8. Selected the 500 GB SSD as the primary installation drive.
9. Configured the administrator credentials and contact email.
10. Configured the hostname and IPv4 network settings.
11. Completed the installation and rebooted the system.
12. Verified that the system booted directly into Proxmox.
13. Accessed the Proxmox web interface and confirmed that the host was operational.

## Verification
The Proxmox installation was verified using both the physical host and the web management interface.

After installation:

- The Proxmox console screen successfully loaded on the host system.
- I used the terminal to verify the host's network and IP configuration.
- I confirmed that the Proxmox management IP was reachable from my main computer.
- I opened the Proxmox web interface in a browser.
- I successfully logged in using the root administrator account and the password created during installation.
- I verified that the Proxmox node appeared online and was accessible through the management interface.

After confirming that the host was operational, I moved on to repository configuration and system updates as part of the next setup stage.

## Issues Encountered
There were no major issues during the initial Proxmox installation itself.

After shutting down the Proxmox host for the first time and powering it back on, I was temporarily unable to access the Proxmox web interface from my main computer.

I suspected the issue was related to the host's network or IP configuration. After restarting the system and verifying the connection, I was able to access the web interface normally again.

Although the issue was minor, it reinforced the importance of checking network connectivity and IP configuration when a remotely managed server cannot be reached.

Some of the main things I learned included:

- How to navigate the system BIOS and verify that the proper virtualization settings are enabled.
- How to create a bootable installation drive using Rufus.
- How a dedicated hypervisor such as Proxmox can be installed directly onto physical hardware.
- How to remotely manage a server through the Proxmox web interface from another computer.
- How to review and verify IP configuration to make sure the host can communicate correctly on the network.
- How important proper network settings are when relying on browser-based remote management.

Overall, this part of the project gave me my first hands-on experience with setting up a dedicated virtualization host from start to finish and helped me become more comfortable with both the hardware and software involved.
