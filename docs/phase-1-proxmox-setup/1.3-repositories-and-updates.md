# 1.3 — Repositories and Updates

## Objective
The objective of configuring the Proxmox repositories and system updates was to make sure the host was fully prepared before creating any virtual machines.

I wanted to verify that Proxmox was using the correct no-subscription repository, that the system could receive updates properly, and that the installed packages were current.

Completing this step helped ensure that the Proxmox host was running on an up-to-date and properly configured software base before moving on to virtual machine deployment.

## Configuration
The default Proxmox enterprise repository was disabled because this homelab does not use a paid Proxmox subscription.

The Proxmox no-subscription repository was then enabled so the host could continue receiving package updates without requiring an enterprise license.

The repository configuration was reviewed to make sure the package sources were valid and compatible with the installed Proxmox version.

## Steps Performed
1. Opened the Proxmox repository settings from the web interface.
2. Identified the default enterprise repository.
3. Disabled the enterprise repository because the homelab does not use a paid subscription.
4. Added and enabled the Proxmox no-subscription repository.
5. Refreshed the available package lists.
6. Reviewed any repository warnings or errors.
7. Corrected the repository configuration where needed.
8. Ran the available system updates.
9. Rebooted the Proxmox host after the updates were completed.

## Verification
The repository and update configuration was verified by:

- Confirming that the no-subscription repository was enabled.
- Confirming that the enterprise repository was no longer being used.
- Refreshing the package lists successfully.
- Verifying that Proxmox could retrieve available updates.
- Installing the available system updates.
- Rebooting the host and confirming that Proxmox started normally afterward.
- Logging back into the Proxmox web interface and confirming that the node was operational.

## Issues Encountered
One issue occurred while configuring the repositories.

During the update process, one of the configured package sources returned an error indicating that the repository did not have a valid Release file. This prevented the package lists from updating correctly.

The repository configuration was reviewed and corrected so that the host was using the appropriate package sources.

After correcting the repository entry, the package lists refreshed successfully and the available Proxmox updates could be installed.

## What I Learned
This part of the project helped me better understand how Linux-based systems use software repositories to retrieve packages and updates.

Some of the main things I learned included:

- The difference between the Proxmox enterprise repository and the no-subscription repository.
- Why a Proxmox installation without an enterprise subscription should not rely on the enterprise repository.
- How incorrect repository configuration can prevent a system from retrieving package updates.
- How to review and correct repository settings when package updates fail.
- Why it is important to update the hypervisor before beginning to deploy virtual machines.
- How system updates can require a reboot before the host is fully running on the updated software.

Overall, this step gave me more hands-on experience with maintaining the software side of a server and showed me how important repository configuration is for keeping a system updated and operational.
