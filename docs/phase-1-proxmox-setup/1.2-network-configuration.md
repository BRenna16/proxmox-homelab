# 1.2 - Network Configuration

## Objective
The objective of the network configuration was to properly configure the Proxmox host's IPv4 settings so the server could be accessed reliably from another computer on the home network.

I wanted to be able to manage the Proxmox host through its web interface using the assigned IP address, while also preparing the system for remote access through Tailscale.

To improve reliability, the Proxmox host was kept connected through Ethernet rather than Wi-Fi so the network connection would remain stable even if the physical system was moved or restarted.

## Configuration
The Proxmox host was configured using the IPv4 settings from my home network.

The network configuration included:

- A static IPv4 address for the Proxmox host
- The correct subnet mask for the home network
- The home router's IP address as the default gateway
- A wired Ethernet connection for stable network access

Using a fixed IPv4 configuration made it easier to consistently access the Proxmox web interface from my main computer without the management address changing.

## Steps Performed
1. Connected the physical Proxmox host to the home network using Ethernet.
2. Entered the required IPv4 network settings during the Proxmox configuration process.
3. Configured the host with the appropriate IP address, subnet information, and default gateway for the home network.
4. Completed the Proxmox network setup and continued with the installation.
5. Verified that the Proxmox web interface could be reached from another computer on the same network.
6. Set up Tailscale for remote access to the Proxmox host.
7. Linked the Proxmox host to the Tailscale network.
8. Used the Tailscale-assigned IP address to access the Proxmox web interface from another device while connected through the Tailscale application.

## Verification
To confirm local network access:

- I used my main PC to connect to the Proxmox web interface using the host's IPv4 address.
- The Proxmox login page loaded successfully.

To confirm remote access:
The network configuration was verified using both local and remote access methods. 

- I used my MacBook with the Tailscale application connected.
- I entered the Tailscale IP address assigned to the Proxmox host.
- The same Proxmox login page loaded successfully.

Successfully reaching the management interface through both methods confirmed that the local IPv4 configuration and Tailscale remote access were working correctly.

## Issues Encountered
There were no major networking issues during the initial configuration.

The main issue occurred when I was temporarily unable to access the Proxmox web interface after the host had been powered on. The browser would not load the management page at first.

I performed a hard reset of the Proxmox host, and after the system restarted, I was able to access the web interface normally again.

This issue reinforced the importance of confirming that the host has fully booted and that network connectivity is available before troubleshooting the browser or IP configuration further.
